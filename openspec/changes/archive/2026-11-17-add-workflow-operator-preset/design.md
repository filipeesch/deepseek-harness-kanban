# Design

## Context

See the proposal for motivation. The task-context hook injects one durable message per conversation; stage instructions are delivered separately. The workflow parser discards stage descriptions and rejects a root description. The persisted parsed workflow is compared to authored YAML; team synchronization and history use normalized meaning as well as exact text. Board default preset selection currently comes from the workflow, and absence means the host default. The turn coordinator persists declared routes without their originating turn and observes multiple task conversations.

The public tool replacement is intentionally breaking. The project and the pinned DSH SDK, not the developer's running profile, are the authority for implementation and tests.

## Goals / Non-Goals

**Goals:**
- Keep a PTC-capable task operator distinct from the architect and project roles, and derive one compact projection for first-turn context and later reads.
- Preserve existing workflows, YAML bytes, explicit defaults, host permissions, automatic mode, script approvals, exact-digest writes, and team data.
- Bind an exceptional declaration to one task entry, session, and completed turn without claiming to verify the natural-language origin of the request.

**Non-Goals:**
- Automatically detect workflow edits in a live conversation, require descriptions or enforce a 150-character limit on people, change normal route persistence, or redefine automatic mode.
- Authenticate natural-language intent, grant authoring tools to the operator, change scripted exit authority, or run real-model acceptance traffic.

## Decisions

### 1. A PTC-based operator, not a workflow author

Compose a sibling operator preset from the actual supported PTC composition: preserve its executor, tool access, host instructions, plan mode, skills, delegation, and safety behavior, and add short workflow-specific guidance. Validate against the pinned host and isolated composition; do not assume preset inheritance exists. Prefer supported reuse over duplicating a large configuration; if duplication is unavoidable, add a drift check against the pinned PTC. Keep the persona concise and do not remount the Kanban host. Its rules describe agentic, scripted, and manual/no-instruction stages, require current route discovery before declaring, and prohibit an unsolicited declaration. A direct user request is distinct from a peer request. Follow workflow and user decisions about questions. The role mask and board MCP policy remain independent; the architect's design-only gate remains closed to the operator.

### 2. New-board default without rewriting an authored document

Treat an explicit authored agent_preset or explicit host-default selection as authoritative. For a newly created board lacking a user choice, record a versioned board-default selection of the operator in board-owned, shareable metadata, separate from authored YAML. This avoids adding bytes to a supplied document and breaking expect_sha256, dry-run, or exact-document guarantees. Distinguish implicit operator default, explicit host default, and legacy absence; existing boards with an absent field remain on the host default. Surface effective choice and origin in board settings; selecting another preset or host default persists the explicit choice. At creation, a supplied authored preset wins. For a later explicit settings change, atomically update the YAML field and board metadata: choosing a named preset writes that identity into YAML and clears the metadata override; choosing host default removes the YAML field and records an explicit host-default marker. Reviewed writes compute their digest over the exact final authored bytes. Metadata must never silently override a still-present authored preset. Editing a preset must not mutate another board or existing session. Preserve host-default fallback and report when the operator preset is unavailable.

Update schema validation, revisions, team publication, replay, conflict handling, and recovery for this metadata rather than silently reinterpreting absence. Existing YAML agent_preset remains supported and exact YAML stays authoritative for that authored field. Shared new boards preserve their selection; importing or receiving an already-authored board is not reclassified as a newly created board. A generated default YAML could carry an explicit preset instead, but treating that as the sole mechanism would fail custom-document creation or alter supplied digests.

### 3. One compact projection with explicit snapshot semantics

Build a pure workflow-summary projection behind a narrow input port: workflow description; initial stage; stages with identifiers, names, optional descriptions, and script/agent-instruction/no-instruction type; route policy with targets and documentary conditions or named script exits; board project scope and sharing; and current task stage plus automatic-mode enabled/paused/held state only when the requested board is the calling task's board. Absence and unknown/unavailable states are explicit, never fabricated. No code, full entry prompts, layout, task counts, YAML, model settings, preset settings, MCP list, or Hub revision is included. Keep the distinction between unrestricted, explicitly empty, configured and scripted routes; conditions are not executable predicates.

Render the same projection into the first native task-context message for every preset, labeled as a first-contact snapshot, and expose it through get_workflow_summary for a live read. Resolve the initial snapshot at the first pre-step; retain existing at-most-once, no-backfill, no-new-turn, native context-row, failure and resume behavior. No initial tool call, subscription, fingerprint, or automatic refresh is needed. list_allowed_transitions remains the authority immediately before an agent decides a transition. Board scope must never imply that a task from another board is current. Bound the rendered workflow portion of the first-turn snapshot and each tool page to 6 KiB of UTF-8, preserving the task identity and current stage first. At a record boundary, mark omitted content and counts explicitly and provide a continuation cursor in the tool; never silently truncate an individual description or condition. If one authored record alone exceeds the budget, return an explicit oversized-record indication and a paginated exact-text read through the same authorized summary tool. Normal-sized snapshots require no startup call; an operator needing omitted details can request the relevant page.

Remove get_board_summary from the registry and migrate product-tool names, masks, descriptions, docs, specs, and consumers. Reuse existing scoped reads for information no longer included; do not widen project-role masks or expose exact YAML to them. The architect retains get_board_yaml, get_stage, and Hub revision reads under the existing architect-only gate. Extend the architect-only board document read with the effective default preset and its origin so a choice stored outside YAML remains inspectable; exact YAML text and digest remain unchanged. Other roles retain existing scoped reads where authorized. The first-turn message is a snapshot, not authority for a changed stage or policy.

### 4. Optional descriptions with compatibility at every boundary

Retain optional workflow and stage descriptions in the domain projection and authored YAML. Missing or blank descriptions are represented as absent, not generated; preserve authored content and exact text on unrelated edits. The architect's concise 150-character limit is guidance, not schema validation. Read legacy boards, including stage descriptions previously omitted from stored normalized state, through a versioned migration or equivalent compatibility projection before strict consistency checks; do not rewrite authored YAML or hashes merely to load it. Include descriptions in revision/diff, publication, semantic comparison, creation events, incremental updates, merge/conflict detection, replay and restore. Publish descriptions and preset metadata only in a capability-versioned team format with an enforceable storage/concurrency compatibility gate. A peer without support must be unable to overwrite the newer representation; where the provider cannot enforce that boundary, fail closed for synchronization and report the incompatibility instead of assuming older clients cooperate. Add fields to authoring and any editing surface needed to create or maintain them while preserving unrelated YAML and approvals. With the providers this release supports, that gate is not enforceable against an older writer, so publication and synchronization of the new fields fail closed and the local board stays a draft; sharing them between compatible installations is deferred to a separate change that can add an isolated representation and its conflict handling.

### 5. Turn-bound exceptional intent, with no false authorization claim

Keep ordinary configured transitions and their existing persistence semantics. Extend set_next_transition with an explicit exception flag only for a different existing destination not configured by the current non-scripted stage. The tool instructions require a direct explicit user request in that task conversation; stage instructions, peers, and the model's own decision do not supply that request. The flag is model-provided, so it is not independent proof of human intent; add no confirmation and make no stronger claim. Extend transition discovery with an optional explicit destination lookup that reports only its declared parameter names and descriptions, including for an unconfigured target, without implying it is allowed or revealing script code; use this before declaring an exception with required parameters. Validate reason, scope, destination, exact parameters, stage entry, pending work and destination script approvals as before. Script-controlled entries and script exits never gain a generic override.

Attach an exception identity to the exact task entry, calling session, open turn, source and destination and carry it through resolution and admission. Only the matching observed turn/end with reason.kind = completed can consume it. The ordinary coordinator's task-wide turn event is insufficient; neither a different conversation nor a later turn may consume it. Revalidate identity, current entry, recorded value, destination and guards in the serialized admission transaction. If the owner turn fails, aborts, is interrupted, cannot be verified, or cannot be admitted because the task is held or busy, discard or invalidate the unadmitted exception; auto mode must not resurrect it as its destination. A successfully admitted advance remains durable under existing dispatch/recovery. On restart or lost identity, fail closed for an unadmitted exception; never replay an unobserved turn. An accepted exception replaces the previous recorded declaration and expiration does not restore it; conditional cleanup compares the unique exception identity and must never clear a newer concurrent declaration. Preserve independently enabled automatic mode's normal behavior after the exception is gone.

Use the pinned host's non-deprecated turn-boundary and event contracts if available; check exact version and semantics before use. If the pinned host cannot identify the open turn safely, refuse exceptional declaration with an actionable result rather than guessing or using deprecated session APIs. Use injected ports for identity, event observation, task persistence, and admission so races and restarts are deterministic in tests. Keep manual restricted-move confirmation, destination entry behavior and scripted approvals intact.

### 6. Neutral transition briefing

Keep the existing briefing and its ordering but make its wording descriptive and conditional: it may explain how the declaration works and that it advances on completion, but it must not command a declaration solely because two destinations exist. An authored instruction or explicit user request may still direct it. The automatic-mode controller remains separate and unchanged.

## Risks / Trade-offs

- [Instruction-only user authorization] -> Clearly document that a model can violate it; the exception flag is not a human credential. Preserve deterministic non-intent guards and normal manual confirmation.
- [Two persistence domains and concurrent task conversations] -> Bind and revalidate the exception; fail closed for an unobserved or stale turn; test crash and replay boundaries. Do not infer completion from an aggregate that conflates aborted and completed turns.
- [Legacy normalized state and mixed-version sharing] -> Version or migrate representation without rewriting YAML; round-trip old descriptions and fail explicitly when peers cannot preserve new content.
- [Drift from host PTC] -> Test isolated composition against the pinned host; check every touched host API for deprecation and use a local port when a direct integration is unavailable.
- [Summary size and staleness] -> Keep a single bounded projection with explicit truncation/continuation if needed; label first-contact data and use live transition discovery for routing.
- [Breaking product-tool removal] -> Update shipped presets, role masks, docs, examples and deterministic tests together; external integrations must switch tools.

## Migration Plan

1. Read legacy data without changing authored text; upgrade internal normalized projections and new-board metadata in a version-aware manner. Existing absent preset values retain host-default meaning.
2. Publish the new preset and tool replacement together with adapted roles and authoring guidance. Create new boards with the new default and preserve explicit existing choices; report unavailable host presets.
3. Version team sharing/replay as needed, test old-to-new and unsupported new-to-old peers, and refuse unsafe replay rather than losing descriptions or defaults. No automatic publication occurs.
4. Rollback must preserve original YAML, existing board settings, and team data. If an older version cannot read new metadata or root descriptions, prevent unsafe downgrade/synchronization and require a compatible version or explicit reviewed export rather than discarding fields.
